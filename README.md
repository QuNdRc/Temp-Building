# Temp-Building — арсенал заготовок для строительного хакатона

Набор переиспользуемых шаблонов (C++ / Python) для типовых задач строительных
кейсов: оптимизация, сетевые графики и риски, данные, геометрия, компьютерное
зрение, разбор документов через LLM, инженерные расчёты, назначение ресурсов,
генерация пояснительной записки в Word.

> **Единая точка входа:** [`run.py`](run.py)
> **Архитектура и уроки:** [`ARCHITECTURE.md`](ARCHITECTURE.md)

## Структура

```
├── run.py                     единая точка входа (list / run / new)
├── ARCHITECTURE.md            карта проекта: шаблоны vs решения кейсов
├── requirements.txt           Python-зависимости
│
├── 01_optimization_cpp/       перебор вариантов: hill climbing, отжиг (C++)
├── 02_cpm_monte_carlo/        CPM, критический путь, Монте-Карло рисков (C++)
├── 03_data_pipeline_py/       CSV/JSON → pandas → агрегаты → аномалии → график
├── 04_llm_json_py/            локальная LLM по HTTP → гарантированный JSON
├── 05_geometry_py/            shapely: пересечения, площади, раскрой, покрытие
├── 06_computer_vision_py/     OpenCV: контуры, дефекты, разметка фото
├── 07_calcs_cpp/              Wood–Armer + послойное суммирование осадки (C++)
├── 08_docs_rules_py/          LLM-разбор документа → проверка по правилам
├── 09_assignment_cpp/         венгерский алгоритм назначения бригад (C++)
├── 10_report_docx_py/         генератор пояснительной записки в Word
│
└── tests/
    ├── case1/   ТРЕНИРОВОЧНЫЙ кейс «Стройгенплан» (выдуман для тестов)
    ├── case2/   ТРЕНИРОВОЧНЫЙ кейс «Бытовой городок» (выдуман для тестов)
    ├── case3/   ТРЕНИРОВОЧНЫЙ кейс «Модель, смета, график» (выдуман для тестов)
    └── hak/     РЕАЛЬНЫЙ кейс хакатона №11 (концепция жилого дома)
```

## Важно про папку tests

**`case1`, `case2`, `case3` — выдуманные тренировочные кейсы.** Они написаны
автором проекта специально, чтобы обкатать заготовки на известных эталонах
(в папках `answers/` и `KEY3_dont_open_before/` лежат эталонные решения и
скрипты проверки). Их цель — проверить, что шаблоны работают end-to-end и
поймать грабли (единицы измерения, AABB-пересечения, связка CV↔оптимизация).

**`hak/` — настоящий кейс строительного хакатона** (концепция многофункционального
жилого дома, ЦАО): расчёт ТЭП, жителей, соцобъектов, подземного паркинга,
озеленения, бюджета и сроков с явными допущениями. Решается одним файлом
[`tests/hak/solve.py`](tests/hak/solve.py).

Тренировочные результаты сверены с эталонами:

| Кейс | Статус сверки |
|---|---|
| case1 | часть 2 cost 3068.1 (отношение 1.000 к эталону), часть 3 совпала; часть 1 IoU 0.35–0.99 |
| case2 | все три части совпали с эталоном 1-в-1 |
| case3 | официальный `score_case3.py`: инвентарь, R1–R8, смета и срок — 100% совпадение |

## Быстрый старт

```bash
pip install -r requirements.txt

python run.py               # список шаблонов и кейсов
python run.py run case2     # запустить решение тренировочного кейса
python run.py run 02_cpm_monte_carlo   # запустить демо шаблона
python run.py new caseX     # каркас нового кейса в tests/caseX/
```

Компиляция C++-шаблонов (MSVC или g++):

```bash
cl /std:c++20 /O2 /EHsc 01_optimization_cpp\main.cpp /Fe:01_optimization_cpp\optimize.exe
g++ -O2 -std=c++20 02_cpm_monte_carlo/main.cpp -o cpm
```

## Карта «задача → шаблон»

| Задача на кейсе | Шаблон |
|---|---|
| Расставить объекты минимальной стоимостью (кран, склады, бытовки, раскрой) | `01_optimization_cpp` |
| Сроки, критический путь, резервы, вероятность уложиться | `02_cpm_monte_carlo` |
| Почистить/свести таблицы, найти аномалии, выдать график | `03_data_pipeline_py` |
| Вытащить поля из акта/документа через локальную LLM | `04_llm_json_py` |
| Площади, пересечения, расстояния, упаковка на плоскости | `05_geometry_py` |
| Дефекты/объекты по фото, разметка «до/после» | `06_computer_vision_py` |
| Плита (Wood–Armer), осадка фундамента | `07_calcs_cpp` |
| Проверить документ/модель по набору правил → отчёт о нарушениях | `08_docs_rules_py` |
| Назначить бригады/технику по объектам (минимум стоимости) | `09_assignment_cpp` |
| Собрать результаты в пояснительную записку (Word) | `10_report_docx_py` |

## Принципы

- Шаблоны автономен и headless: запускаются одной командой, пишут результаты
  в файлы (`results.json`, `*.docx`, `*.png`) — консоль не единственный выход.
- Проверка ограничений оптимизации ведётся по аналитической геометрии,
  а не по результатам распознавания (урок case1).
- Все недостающие нормы оформляются как **явные допущения** и перечисляются
  в отчёте отдельным разделом (практика hak-кейса).
- Единицы читаются из данных (`IfcSIUnit`, масштаб по линейке), а не угадываются.
